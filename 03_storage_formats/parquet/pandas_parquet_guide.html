Шпаргалка инженера данных: Pandas, PyArrow и Apache Parquet

1. Архитектура: кто за что отвечает

Компонент Где живёт Роль в системе Зачем нужен
Pandas Оперативная память (RAM) Таблицы DataFrame Быстрые вычисления, фильтрация, группировка (.groupby), агрегация (.agg).
Apache Parquet Диск / S3 / DWH Колоночный бинарный файл Экстремальное сжатие, чтение только нужных колонок, хранение строгих типов данных.
PyArrow Движок (библиотека на C++) Мост между RAM и диском Физически упаковывает таблицы Pandas в бинарные байты Parquet и читает их обратно.
Важно: Мы пишем import pandas as pd. Библиотеку pyarrow импортировать в код не нужно — Pandas подключает её сам под капотом при вызове to_parquet() и read_parquet().

2. Строчные форматы vs Колоночный Parquet

  • Строчные (CSV, JSON, Avro): Данные пишутся строка за строкой. Чтобы посчитать среднюю сумму заказа в таблице на 100 ГБ, компьютеру придётся прочесть с диска все 100 ГБ целиком (включая ненужные имена, адреса и даты).
  • Колоночный (Parquet): Данные хранятся стопками колонок. Для подсчёта суммы скрипт читает с диска только байты колонки amount, полностью пропуская остальные данные.
  • Сжатие: Однотипные данные в колонке упаковываются алгоритмом snappy в 5–8 раз плотнее, чем обычный текст CSV.

3. Сводная таблица форматов данных

Формат Тип Сжатие Выборка колонок Как обращаться к строке Сфера применения
CSV Текст Нет Нет (весь файл) row[2] (список) или row['col'] Excel, простые ручные выгрузки
JSON Текст Очень слабое Нет (весь файл) row['field'] (словарь) API сайтов, веб-приложения, конфиги
Avro Бинарный Высокое Нет (вся строка) row['field'] (словарь) Apache Kafka, потоковая обработка
Parquet Бинарный Максимальное Да (мгновенно) Векторно через DataFrame Хранилища данных, аналитика, Spark, DWH

4. Основные команды и практический синтаксис

А. Чтение и сохранение Parquet

import pandas as pd

# 1. Сохранение таблицы на диск (index=False отключает служебные номера строк)
df.to_parquet('orders.parquet', engine='pyarrow', compression='snappy', index=False)

# 2. Быстрое чтение ТОЛЬКО нужных колонок (экономит до 90% оперативной памяти)
df_sub = pd.read_parquet('orders.parquet', columns=['status', 'amount'])

# 3. Чтение файла целиком
df = pd.read_parquet('orders.parquet')

Б. Фильтрация данных (Boolean Masking)

# Одиночное условие (скобки можно опустить)
paid = df[df['status'] == 'paid']

# Несколько условий: ОБЯЗАТЕЛЬНО круглые скобки (...) и символ & (И) или | (ИЛИ)
target = df[(df['status'] == 'paid') & (df['amount'] >= 1000)]

В. Группировка и расчёт метрик (.groupby + .agg)

# Одна метрика: считаем только сумму amount для каждого города
revenue = df.groupby('city')['amount'].sum()

# Несколько метрик по одной колонке (список функций)
stats = df.groupby('city')['amount'].agg(['count', 'sum'])

# Именованная агрегация (Named Aggregation) — самый чистый вариант для продакшена:
city_summary = df.groupby('city').agg(
    total_orders=('order_id', 'count'),   # количество заказов
    total_revenue=('amount', 'sum'),      # сумма выручки
    avg_check=('amount', 'mean')          # средний чек
).reset_index()
